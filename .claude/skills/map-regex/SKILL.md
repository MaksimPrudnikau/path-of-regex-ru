# Regex модов карт

## Как устроена строка поиска PoE

- Строка — набор термов в кавычках через пробел: `"!вож|к ш" "Ур. 1[6-7]" "^Кол.+: \+(8\d|9\d)%"`.
- Термы между собой — **AND**, `|` внутри терма — **OR**, `!` в начале терма — **отрицание всего терма**.
- Терм — обычный regex по всему тексту предмета; `^`/`$` работают по строкам. Неизвестно, учитывает ли игра регистр и как склеивает строки (`\n` или пробел), поэтому regex обязан работать **во всех четырёх режимах** — это и проверяют скрипты.
- Длина строки ограничена: UI показывает `Длина: N / 250` (`RegexValue.tsx`). Поэтому regex мода — **кратчайшая подстрока**, однозначная среди всех текстов карт.
- «Исключить A и B одновременно» синтаксисом не выразить: T17-мод, целиком составленный из строк обычных модов, одним regex не отличить. `regex:simulate` выводит такие моды как «составленные из строк других модов» — это ожидаемо, не ошибка.

## Данные

- `data/maps.sqlite`, таблица `maps (id, name, rank, regex, uniqueIndex)`:
  - `name` — строки мода как в игре, через ` · `; запятые внутри строки заменены на `;` (`skeleton` в `lib.mjs` возвращает их обратно).
  - `rank` — опасность мода: `0` безопасный, `1–699` от слабого к опасному (цвет в `Mod.tsx`), `>= 700` — T17 (показываются только при `includeT17`, `ModsSearchTable.tsx`).
  - `regex` — терм без кавычек, кладётся в `negativeMods`/`positiveMods` профиля.
- В бандл таблица попадает при сборке через `virtual:map-mods` (`app.config.ts` → `src/api/index.ts`). Профили пользователей хранят копию `{ id, regex }` в `localStorage`: изменённый regex у уже выбранных модов обновится только после повторного выбора мода — учитывай это, если меняешь regex массово.
- Эталон игры — `scripts/map-regex/data/poedb-map-mods.json` (все тиры `low/mid/top/uber`, группы `normal`/`delve`). Латинские строки в нём — скрытые статы, скрипты их отбрасывают.
- `scripts/map-regex/lib.mjs`:
  - `SERVICE_LINES` — текст, который есть на любой карте; regex мода не должен его задевать. Новые служебные строки (новая механика, влияние) добавляй сюда.
  - `ALIASES` — когда название в БД расходится с текстом poedb после патча: ключ — скелет из БД, значение — скелет реального текста.
  - `HIDDEN` — строки, которые игра суммирует в свойства карты и не показывает на предмете.

## Скрипты

| Команда | Что делает | Время |
|---|---|---|
| `bun run regex:fetch` | Скачивает эталон с poedb.tw (сеть; перезаписывает JSON) | секунды |
| `bun run regex:check` | Сверяет regex каждого мода с эталоном, выводит `#id "старый" -> "предложенный" [проблемы]`, exit 1 при ошибках | ~1 мин |
| `bun run regex:check -- --apply` | То же + записывает предложенные regex в `data/maps.sqlite` | ~1 мин |
| `bun run regex:check -- --file mods.json` | Проверяет моды из JSON вместо БД | ~1 мин |
| `bun run regex:simulate` | Генерирует случайные карты, строит строку настоящим `buildRegex` и проверяет подсветку в 4 режимах (регистр × склейка), включение/исключение каждого мода и чекбоксы | ~1 с |

`regex:check` долгий — запускай в фоне. Ожидаемый чистый результат: `проверено N, с ошибками 0` и `проверок: …, ошибок: 0`.

## Процессы

### Поправить regex одного мода
1. Найди мод: `sqlite3 data/maps.sqlite "select id, name, rank, regex from maps where name like '%шипами%'"`.
2. Запусти `regex:check` — он сам предложит кратчайший корректный вариант. Бери предложенный, а не придумывай руками.
3. Примени: `regex:check -- --apply` (обновляет только строки, где `regex` не менялся с момента проверки) или точечно `sqlite3 data/maps.sqlite "update maps set regex = '…' where id = …"`.
4. Повтори `regex:check` и `regex:simulate` — оба должны пройти без ошибок.

### Обновить данные после патча PoE
1. `regex:fetch` → посмотри `git diff --stat scripts/map-regex/data/`.
2. `regex:check`: моды «не найден на poedb» — текст изменился. Либо обнови `name` в БД под новый текст, либо добавь запись в `ALIASES`.
3. Новые моды добавляй `insert` в `maps` с корректным `rank`, затем `regex:check -- --apply` подберёт regex.
4. Финал — `regex:check`, `regex:simulate`, `bun run build`.

### Правка `buildRegex` / `regex-builders`
- `buildRegex(store: MapsStore): string` и `regex-builders/*` — чистые функции без Solid, DOM и `localStorage`: их импортирует `simulate.ts`. Не тащи туда реактивность или `alert`.
- Числовые фильтры собираются через `addIfHas(range, "шаблон {0}", config)`; шаблон — короткий якорь по русскому тексту свойства (`"^Кол.+: \\+{0}%"`), `{0}` заменяется диапазоном из `to-regex-range` (`modRange.builder.ts`). Новый фильтр: поле `ModRange` в `MapsStore` + значение в `initialMapsContextState()` + строка `addIfHas` + проверка в `simulate.ts`.
- Невалидный диапазон — `throw new Error("…")` на русском: `RegexAreaContextProvider` ловит его и показывает текст пользователю, оставляя прошлую строку.
- Чекбоксы (`includeNormalMaps`, `includeCorruptedMaps`…) — `addCheckbox(flag, IncludeMapType, regex)`, `Exclude` добавляет `!`.
- После правки — `regex:simulate` обязательно; если поменялся формат вывода, обнови и проверки в `simulate.ts`.

## Чего не делать
- Не подбирай regex «на глаз» по названию мода в БД — проверяется только реальный текст игры из эталона.
- Не используй латиницу (её нет в тексте предмета) и `\b`: в JS он не видит границ кириллических слов, поэтому скрипты проверят такой regex неверно.
- Не обрезай число посередине: `500` найдёт и `1500`.
- Не правь `poedb-map-mods.json` руками — только через `regex:fetch`.
